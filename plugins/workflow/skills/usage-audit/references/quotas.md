# Quota snapshot

**This file is a dated snapshot, not the truth.** Free and hobby tiers move.
Every number below carries the date it was read and the page it was read from.

Rules for using it:

1. **The provider's dashboard beats this file, always.** The file tells you the
   shape of the meter; the dashboard tells you where the app actually is.
2. **Check the `Last verified` line before quoting anything.** If it is more than
   about 90 days old, re-verify against the source URL before the number enters
   a report.
3. **Re-verifying is a toolbox change.** Update the numbers *and* the date, then
   propose the plugin version bump. Do not edit this file silently mid-audit.
4. **A row marked `not verified` is not a number.** Go read the page or leave
   the claim out.

## Convex

**Last verified: 2026-08-29** — source: <https://www.convex.dev/pricing>

Convex's free tier is the **Starter** plan. Its meters:

| Meter | Starter (free) | Professional | What drives it |
|---|---|---|---|
| Function calls | 1M included / month | 25M included | every query, mutation and action invocation — including each re-run of a subscribed query |
| Database I/O | 1 GB included | 50 GB included | bytes read and written by functions; a full-table scan bills the whole table |
| Database storage | 0.5 GB included | 50 GB included | document data at rest |
| File storage | 1 GB included | 100 GB included | files in `ctx.storage` |
| Data egress | 1 GB included | 50 GB included | bytes sent to clients |
| Action compute | 20 GB-hours included | 250 GB-hours | wall time x memory of actions, including Node actions |
| Search storage | 0.5 GB included | 1 GB included | search index size |
| Search queries | 3,000 query-GBs included | 50,000 query-GBs | search reads |
| Team members | 1–6 developers | 1–20 | |
| Concurrent sessions | 1,000 | 10,000 | open websocket clients |
| Concurrent queries | 16 | 256 | |
| Concurrent actions | 64 | 512 | |

Not on the pricing page, and therefore **not verified**: per-project limits,
vector storage allowance, preview deployment count. Read the docs or the
dashboard before quoting any of those.

**The meters that surprise people:** *function calls* counts every re-run of a
live query, not every distinct query you wrote — a subscribed query over a table
that is written often bills once per push, per subscriber. And *database I/O* is
charged on bytes scanned, so an unindexed filter over a large table is expensive
even when it returns one document.

## Cloudflare Workers

**Last verified: 2026-08-29** — source:
<https://developers.cloudflare.com/workers/platform/limits/>

| Limit | Free | Paid |
|---|---|---|
| Requests | 100,000 / day (resets 00:00 UTC) | no daily limit |
| CPU time per invocation (HTTP) | 10 ms | 5 min |
| Memory per isolate | 128 MB | 128 MB |
| Subrequests | 50 / request | 10,000 / request |
| Worker size (compressed) | 3 MB | 10 MB |
| Environment variables | 64 / Worker | 128 / Worker |
| Number of Workers | 100 | 500 |
| Cron triggers | 5 | 250 |
| Static asset files | 20,000 | 100,000 |

Both plans: individual static asset file 25 MiB, env var 5 KB, startup time 1 s,
6 simultaneous open connections per request.

**The 10 ms CPU ceiling is the one that bites an SSR app**, not the request
count — it is CPU time, so awaiting a slow backend does not count against it,
but rendering a large tree does.

| Value size | 25 MiB |

Delete and list allowances are **not verified** — the limits page does not state

**1,000 writes/day is the trap.** KV is a read-optimized store; anything that
writes per request will exhaust the free write allowance long before the read
allowance.

## Cloudflare R2

**Last verified: 2026-08-29** — source:
<https://developers.cloudflare.com/r2/pricing/>

| Meter | Forever-free allowance |
|---|---|
| Storage | 10 GB-month |
| Class A operations | 1M / month |
| Class B operations | 10M / month |
| Egress | free |

Standard storage only — the free tier does **not** apply to Infrequent Access.

- **Class A** (the expensive class, 10x scarcer): `PutObject`, `CopyObject`,
  `ListObjects`, `ListBuckets`, `CreateMultipartUpload`, `UploadPart`,
  `UploadPartCopy`, `ListParts`, `CompleteMultipartUpload`,
  `ListMultipartUploads`, `PutBucket*`, lifecycle tier transitions.
- **Class B**: `GetObject`, `HeadObject`, `HeadBucket`, `GetBucket*`,
  `UsageSummary`.
- **Free**: `DeleteObject`, `DeleteBucket`, `AbortMultipartUpload`.

**`ListObjects` is Class A.** A listing per page view is billed like a write.

## Cloudflare D1

**Last verified: 2026-08-29** — source:
<https://developers.cloudflare.com/d1/platform/pricing/>

| Meter | Free |
|---|---|
| Rows read | 5M / day |
| Rows written | 100,000 / day |
| Storage | 5 GB total |

Per-database storage and database count are **not verified**.

**Rows read counts rows scanned, not rows returned.** A full scan of a
5,000-row table is 5,000 rows read even if the query returns one. Row size does
not matter. `INSERT`, `UPDATE` and `DELETE` each count one row written per row
affected. This makes missing indexes a direct, linear cost.

## Cloudflare Durable Objects

**Last verified: 2026-08-29** — source:
<https://developers.cloudflare.com/durable-objects/platform/pricing/>

Available on the Workers Free plan, **SQLite storage backend only**.

| Meter | Free |
|---|---|
| Requests | 100,000 / day |
| Duration | 13,000 GB-s / day |
| Rows read | 5M / day |
| Rows written | 100,000 / day |
| Stored data | 5 GB total |

Daily limits reset at 00:00 UTC, and exceeding any one of them makes further
operations **of that type** fail with an error rather than degrading.

**Duration is wall-clock while the object is alive**, so an object kept awake by
an open WebSocket bills continuously whether or not messages flow.

## Clerk

**Last verified: 2026-08-29** — source: <https://clerk.com/pricing>

| Meter | Free (Hobby) |
|---|---|
| Monthly Retained Users (MRU) | 50,000 / app |
| Monthly Retained Organizations (MRO) | 100 / app, free on all plans |

Clerk bills **retained** users, not active ones: a user counts only if they
return at least 24 hours after signing up. Sign-up spikes and bot traffic
therefore do not bill the way an MAU meter would.
